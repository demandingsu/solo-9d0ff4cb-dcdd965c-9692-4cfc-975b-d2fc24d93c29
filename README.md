# 夜班接驳车末班核定 + 时刻勘误回填

两个给夜班通勤协调员 / 站务数据员用的 Web 工具：

1. **末班核定**（`/`）：输入时刻表首页 URL、上车站、下车站、最早出门与
   到岗截止的日期时间，自动翻页抓取两站时刻表，按**车次号 + 停站顺序**配对，
   只保留“发车不早于出门、到站不晚于截止”的班次，给出**发车最晚的一班**及两站来源。
2. **勘误回填**（`/backfill`）：把核准的接驳时刻勘误写回运营门户，供下游采集。
   填写门户 URL 与勘误表（站名、车次号、服务日类型、原时刻、新时刻），
   应用沿分页读取整页编辑表单，逐行核对后整页提交，提交后回读门户逐项核验。

## 勘误回填的作业流程

1. **沿分页读取**：从门户首页的 `a.edit-entry`（或直接的编辑页 URL）进入，
   沿 `a.next-page` 读完全部编辑页；同一会话携带表单里的隐藏令牌（`_token`）
   与页修订号（`_revision`）提交，门户拒绝过期修订（HTTP 409）。
2. **提交前逐行核对**：门户现值**仍为原时刻才改**；**已是新时刻则跳过**；
   **其他值报冲突**（不改动）。
3. **整页提交**：无关行按读到的现值原样带回，不会丢行；**没有待改行的页不提交**。
4. **页修订冲突**：HTTP 409 后重读该页，按同一规则**最多重试一次**。
5. **回读核验**：提交（或提交异常）后重新读取门户逐项核对——
   新时刻=**确认完成**，原时刻=**未完成**，其他值=**冲突**，读不到=**待核实**；
   **提交响应中断也只核验、不自动重提**。
6. 结果页逐项展示状态、门户现值、**来源页**链接与过程记录，另附页面级提交日志。

## 功能要点（末班核定）

- **分页抓取**：从首页的站点链接（`a.station-link`）找到两站第 1 页，沿
  `a.next-page` 逐页抓取，直到没有下一页（50 页上限、循环链接保护）。
- **配对规则**：两站记录车次号相同，且上车站停站顺序早于下车站才视为同一行程。
- **服务日区分**：按车次**始发服务日**标注工作日（周一至周五）/ 周末（周六周日）/
  每日；查询时按时间窗覆盖的每个始发日分别判断是否运行。
- **24:xx 跨日时刻**：`24:25`、`25:10` 等按“始发服务日零点 + 时间差”换算为真实
  日期时间；若下车站时刻（如 `01:00`）早于上车站发车（如 `23:50`）且未用 24 小时
  制书写，自动按次日处理。
- **异常提示**：
  - 任一分页抓取失败 / 表头缺列 / 链接循环 → 提示“无法核定末班”，且不展示不可信结论；
  - 车次缺停站顺序、缺关键时刻、两站服务日标注不一致、下车站无该车次记录 →
    逐条告警；若仍有其他完整班次，正常给出末班，告警与答案同时展示。
- 结果页展示末班车次、服务日类型、两站实际到发时间与原始时刻、两站来源 URL，
  以及时间窗内全部可选班次。

## 目录结构

```
.
├── app/                  # 末班核定 + 勘误回填 Flask 应用（端口 5000）

│   │   ├── times.py      # 纯逻辑：时刻解析、服务日、配对核定（可单测）
│   │   ├── scraper.py    # requests + BeautifulSoup 分页抓取
│   │   ├── backfill.py   # 勘误回填：分页读取、逐行核对、提交与回读核验（可单测）
│   │   ├── app.py        # Flask 路由与表单校验（/ 与 /backfill）
│   │   └── templates/    # index.html、backfill.html
│   ├── tests/            # 单元 / 端到端测试（末班核定 + 回填全流程）
│   ├── Dockerfile
│   └── requirements.txt
├── example-site/         # 本地示例时刻网站（端口 5001）
│   ├── app.py            # 含分页、24:xx 跨日、工作日/周末、缺记录与 500 故障站
│   ├── Dockerfile
│   └── requirements.txt
├── portal/               # 本地示例运营门户（免登录，端口 5002）
│   ├── app.py            # 分页编辑表单、令牌+页修订号校验、409 拒绝过期修订、
│   │                     #   /demo 演示控制台（并发改表 / 保存后响应中断 / 重置）

```

- 示例运营门户：<http://localhost:5002/>（演示控制台 <http://localhost:5002/demo>）
- 末班核定应用：<http://localhost:8000/>（勘误回填 <http://localhost:8000/backfill>）

在核定页面填写：

| 字段 | 示例值 |
| --- | --- |
| 时刻表首页 URL | `http://example-site:5001/`（容器间用服务名访问） |

> `http://example-site:5001/`。

## 用浏览器完成一次勘误回填

1. 打开 <http://localhost:8000/backfill>，门户 URL 填 `http://portal:5002/`
   （容器内服务名；本地直跑时填 `http://127.0.0.1:5002/`），勘误表已预填三行样例：
   ```
   滨河园区,N201,工作日,22:30,22:35
   中央厂区,N202,每日,24:25,24:30
   夜班宿舍,N204,周末,01:30,01:35
   ```
2. 点「执行回填」：应用读全部 3 个编辑页 → 逐行预检 → 逐页提交 → 回读核验，
   结果页逐项显示「确认完成」与来源页链接。
3. 再点一次「执行回填」：所有行已是新时刻，全部跳过，任何页面都不会再提交
   （门户修订号不变）。

### 演示：并发改表与保存后响应中断

到门户演示控制台 <http://localhost:5002/demo>：

- **并发改表**：点第 1 页「武装并发改表」，再回填涉及第 1 页的勘误
  （如 `滨河园区,N201,工作日,22:30,22:35`）。门户先以“他人”身份把该页末行
  +7 分钟并递增修订号，再拒绝本次提交（409）；回填端重读该页、按同一规则
  重试一次后成功，提交日志里能看到完整的「409 → 重读 → 重试」过程。
  若勘误目标恰好是被并发修改的行，重读后现值既非原时刻也非新时刻，该项报冲突。
- **保存后响应中断**：点第 2 页「武装响应中断」，再回填涉及第 2 页的勘误
  （如 `中央厂区,N202,每日,24:25,24:30`）。保存实际生效但响应中途断开；
  回填端不自动重提，只做回读核验，该项仍为「确认完成」。
- **重置数据**：随时可恢复初始时刻与修订号，重复演示。

```bash

cd example-site && python app.py            # http://localhost:5001

# 终端 2：示例运营门户

```

此时首页 URL 填 `http://127.0.0.1:5001/`，门户 URL 填 `http://127.0.0.1:5002/`。

## 试一下异常场景

- **缺记录**：示例数据里 N206 在「中央厂区」没有停站记录，任意
  滨河园区→中央厂区查询都会看到黄色数据告警，末班仍由 N205 等完整数据核定。
- **分页失败**：上车站填「故障北站」，其第 2 页返回 HTTP 500，页面显示红色
  “无法核定末班”，并标明失败的分页地址。
- **周末 vs 工作日**：把时间窗放到周六晚上（如 2026-11-14 22:00 至
  2026-11-15 02:00），结果中只会出现“每日”和“周末”班次。

## 适配真实时刻表站点

抓取器对页面结构的约定（见 `app/commuter/scraper.py`）：

1. 首页上站点链接带 `class="station-link"`，文本为站点名；
2. 站点页有 `<table>`，表头包含 车次号 / 停站顺序 / 站点 / 时刻 / 服务日
   （支持常见别名，如“站序”“班车”“到时”等，见 `_HEADER_ALIASES`）；
3. 翻页链接带 `class="next-page"`；
4. 服务日列出现“工作日/平日/weekday”“周末/双休/weekend”“每日/daily”等字样。

结构不同的站点只需调整 `scraper.py` 中的选择器与表头别名，核心核定逻辑
（`times.py`）无需改动。

## 适配真实运营门户

回填器对门户页面结构的约定（见 `app/commuter/backfill.py` 与 `portal/app.py`）：

1. 门户首页有 `a.edit-entry` 指向编辑第 1 页（回填 URL 直接是编辑页亦可）；
2. 编辑页含一个表单，隐藏字段 `_token`（会话令牌，与 Cookie 对应）和
   `_revision`（页修订号）随表单提交；行元素为
   `tr[data-row-id][data-station][data-trip][data-service]`，
   行内时刻输入框名为 `clock-<行ID>`；
3. 翻页链接带 `class="next-page"`，末页没有该链接；
4. 保存接口对过期修订号返回 HTTP 409。

结构不同的门户只需调整 `backfill.py` 中的选择器与字段名，核对 / 重试 /
回读核验流程无需改动。
